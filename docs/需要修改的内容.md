基于对 src/stores/ 模块的全面分析，发现以下优化点：

## 1. Store 之间存在大量重复模式

__问题__：40+ 个 Store 都有相似的分页查询结构：
- `loading` 状态
- `current` / `size` 分页参数
- `total` 总数
- `fetchXxx` 函数

__建议__：创建 `usePaginatedStore` 基础 composable/store 统一封装分页逻辑

```ts
// 基础分页 Store
function usePaginatedStore<T>(fetchFn: (params: any) => Promise<PageResult<T>> {
  const records = ref<T[]>([])
  const total = ref(0)
  const current = ref(1)
  const size = ref(10)
  const loading = ref(false)
  
  async function loadData(params?: any) {
    loading.value = true
    try {
      const result = await fetchFn({ current: current.value, size: size.value, ...params })
      records.value = result.records
      total.value = result.total
    } finally {
      loading.value = false
    }
  }
  
  return { records, total, current, size, loading, loadData }
}
```

## 2. CRUD 操作返回模式重复

__问题__：每个 Store 的 create/update/delete 都返回 `Promise<boolean>`，但实际很少使用返回值

__建议__：统一返回模式，或创建通用 CRUD 操作封装

## 3. 状态重置函数命名不统一

__问题__：不同 Store 使用不同的重置命名：
- `clearUsers()`
- `clearCategories()`
- `clearArticles()`
- `clearConversationContext()`

__建议__：统一命名为 `reset()` 或 `clear()`

## 4. 单个详情状态与列表状态混用

__问题__：如 `article.ts` 同时管理 `articles` 列表和 `currentArticle` 详情

__建议__：考虑拆分，或明确区分命名（如 `editingArticle`）

## 5. chat.ts Store 过于庞大

__问题__：`chat.ts` (595行) 包含会话、消息、大厅、频道、申请、禁言等多个功能域

__建议__：拆分为更小的模块：
- `useChatConversationStore`
- `useChatMessageStore`
- `useChatLobbyStore`
- `useChatChannelStore`

## 6. 缺少通用的列表操作状态

__问题__：没有统一的"选中项"、"批量选择"状态管理

__建议__：添加 `selectedIds` 和相关操作方法

## 7. Store 间缺乏数据共享机制

__问题__：如 `auth.ts` 和 `article.ts` 都需要用户信息，但没有共享

__建议__：考虑将 `currentUser` 提升到独立 store

## 8. 缺少持久化配置

__问题__：分页参数 `size` 硬编码，没有持久化到 localStorage

__建议__：添加 `usePersistedState` 支持

## 9. 没有请求防抖/节流

__问题__：搜索等场景连续调用时没有防抖

__建议__：添加防抖版本的操作方法

## 10. 状态类型定义分散

__问题__：每个 Store 都在文件内部定义状态类型

__建议__：考虑统一到 `src/types/stores/` 目录
