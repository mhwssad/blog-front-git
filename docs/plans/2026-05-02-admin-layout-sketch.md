# 后台管理页面布局草图

> 基于后端领域模型设计的后台管理页面布局骨架，覆盖全部业务模块。
> 每个页面包含 ASCII 线框图 + 字段来源映射 + 交互要点。

---

> - 移除「审计日志」（无对应 API）、「系列管理」（无后台管理 API）

> - 新增「AI 会话管理」（对应 `sys/ai/sessions` API）
> - 新增「上传任务」（对应 `sys/files/upload-tasks` API）
> - 拆分「频道管理」→「会话管理」（含频道 CRUD）+「大厅管理」（大厅设置 + 置顶消息）
> - 「聊天管理」重命名为「会话管理」，交互流程改为先选会话再查消息

## 全局外壳：AdminLayout

所有后台页面共用同一外壳布局。

```
+--------+----------------------------------------------------+
| LOGO   | 搜索  |  全屏  通知  [头像] 管理员 ▾               |
+--------+----------------------------------------------------+
|        | 面包屑: 首页 > 用户管理                             |
| ◉ 仪表盘 +--------------------------------------------------+
|        |                                                  |
| 系统管理|                                                  |
|  用户   |              <router-view />                     |
|  角色   |                                                  |
|  菜单   |                                                  |
|  配置   |                                                  |
|  日志   |                                                  |
|        |                                                  |
| 内容管理|                                                  |
|  文章   |                                                  |
|  分类   |                                                  |
|  ...   |                                                  |
+--------+----------------------------------------------------+
```

**顶部栏** (h=50px, fixed)
- 左：Logo（可折叠侧栏触发器）
- 中：全局搜索框（支持搜索菜单/用户/文章）
- 右：全屏切换 + 通知角标 + 用户头像下拉（个人中心、退出登录）

**左侧菜单栏** (w=220px, 可折叠至 64px 图标模式)
- 折叠/展开按钮
- 按业务域分组的菜单树，支持多级展开
- 当前激活菜单高亮
- 底部：折叠切换按钮

**内容区**
- 顶部面包屑导航
- 主体 `<router-view />`

## 一、仪表盘

### 1.1 Dashboard `/admin/dashboard`

**数据源**: 5 个独立端点，按需加载

```text
+--------------------------------------------------------------+
| Dashboard    时间范围: [今天 ▼]  [自定义: 开始 ~ 结束]        |
+------------------+------------------+------------------+-------+
| 注册用户         | 文章总数         | 评论数           | AI调用|
| 1,234            | 567              | 2,890            | 3,456 |
+------------------+------------------+------------------+-------+
| 待审文章 | 待审举报 | 作者申请 | 活跃用户 | 消息数          |
| 5        | 3        | 2        | 892      | 12,345         |
+-----------+-----------+---------------+-------------------------+
| 文章趋势 (折线图)             | 社区活跃度                   |
| content API                   | community API               |
+-------------------------------+-----------------------------+
| AI 调用统计 (柱状图)          | 举报处理统计 (饼图)          |
| ai API                        | governance API              |
+-------------------------------+-----------------------------+
```

**数据加载**（5 个独立 API，对应 useDashboardStore）:

- `GET /sys/dashboard/overview` → DashboardOverviewVO: registeredUserCount、activeUserCount、authorCount、articleCount、pendingArticleReviewCount、commentCount、chatMessageCount、aiCallCount、reportCount、pendingReportCount
- `GET /sys/dashboard/content` → DashboardContentVO: articleCount、pendingArticleReviewCount、commentCount、likeCount、collectCount
- `GET /sys/dashboard/community` → DashboardCommunityVO: chatMessageCount、lobbyMessageCount、groupCount
- `GET /sys/dashboard/ai` → DashboardAiVO: aiCallCount、aiSuccessCallCount、aiFailedCallCount
- `GET /sys/dashboard/governance` → DashboardGovernanceVO: reportCount、pendingReportCount、processingReportCount、handledReportCount、rejectedReportCount

**时间范围筛选**（DashboardQueryRequest）: rangeType（today/week/month/all/custom）+ startTime/endTime

## 附录：搜索/筛选通用模式

所有列表页顶部搜索区域遵循统一模式：

```text
+--------------------------------------------------------------+
| [主要筛选] [次要筛选] [下拉筛选] ...         [搜索] [重置]     |
+--------------------------------------------------------------+
```

**原则**: 搜索字段严格对齐 API 的 QueryRequest 类型，不展示 API 不支持的筛选维度。

- 文本输入框：对应 keyword/username/name 等字段，支持模糊搜索
- ID 输入框：对应 userId/authorId/followerId 等，精确匹配
- 下拉选择：对应 status/type/applyStatus 等枚举，支持「全部」选项
- 时间范围：对应 startTime/endTime 或 createTimeStart/createTimeEnd
- 搜索按钮：触发查询并重置到第 1 页
- 重置按钮：清空所有筛选条件

## 附录：超管安全操作

以下操作涉及 MFA（多因素认证），需先调用 `POST /admin/2fa/send-code` 发送验证码，再调用 `POST /admin/2fa/verify` 获取 mfaTicket，后续操作需携带此 ticket：

| 操作 | API | 说明 |
| ------ | ----- | ------ |
| 封禁用户 | `POST /admin/users/{id}/ban` | mfaTicket + banReason |
| 解封用户 | `POST /admin/users/{id}/unban` | mfaTicket + unbanReason |
| 调整等级 | `PUT /admin/users/{id}/level` | mfaTicket + level |
| 调整经验 | `PUT /admin/users/{id}/experience` | mfaTicket + experience |
| 接管账号 | `POST /admin/takeover` | mfaTicket + targetUserId → takeoverToken |
| 角色分配 | `PUT /admin/users/{id}/roles` | mfaTicket + roleIds |
