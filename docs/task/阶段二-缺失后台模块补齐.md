# 阶段二：缺失后台模块补齐

[返回总栏](./后台管理完善计划.md) | [对应清单](./阶段二-缺失后台模块补齐-任务清单.md) | [上一阶段](./阶段一-后台基础闭环校准.md) | [下一阶段](./阶段三-已有后台模块一致性治理.md)

## 1. 阶段目标

把缺失模块从“首版已落地”推进到“正式可验收”，确保 `follow / file / chat` 在页面、Store、API、Mock、菜单、权限和验收层面形成闭环。

## 2. 当前阶段范围

- `follow`
- `file`
- `chat`

本阶段不新增超出 API 文档的新业务能力，只做正式收口与验收。

## 3. 当前基线

- `follow` 已有后台列表页、Store 和 Mock
- `file` 已有列表页、详情抽屉、上传任务页、Store 和 Mock
- `chat` 已有会话治理页、消息详情抽屉、Store 和 Mock
- 以上模块已具备首版页面，但仍需系统校验菜单、权限、交互一致性和正式验收结果

## 4. 输入条件

- 阶段一输出的后台基线结论
- `docs/api文档/follow-api.md`
- `docs/api文档/file-api.md`
- `docs/api文档/chat-api.md`

## 5. 输出交付物

- 三个模块的正式收口结果
- 模块级验收记录
- 菜单、权限、Mock、测试数据一致性确认结果

## 6. 实施策略

- 保持执行顺序：`follow -> file -> chat`
- 每个模块都按页面、Store/API、Mock/测试数据、菜单权限、验收五类任务推进
- 先收口轻模块，再处理复杂模块
- 模块完成后立即更新对应阶段清单状态，不跨模块混做

## 7. 模块拆解

### 7.1 Follow

- 关注关系列表
- 条件筛选
- 异常清理
- 权限与菜单对齐

### 7.2 File

- 文件库列表
- 文件详情抽屉
- 状态切换与删除
- 上传任务查询
- 引用信息展示

### 7.3 Chat

- 会话查询
- 成员管理
- 消息查询
- 消息详情
- 回执查询
- 会话与成员治理动作

## 8. 风险与阻塞

- `chat` 模块复杂度最高，容易在成员、消息、回执三层视图间失控
- `file` 模块涉及文件、引用、任务三类数据源，若验收不细会留下联动缺口
- 菜单与权限如果只校页面不校按钮，会导致“可见但不可控”的假闭环

## 9. 验收标准

- 三个模块均支持分页查询和基础筛选
- 所有关键治理动作有明确结果反馈
- 菜单、权限、页面、Store、Mock 一致
- 模块级清单达到可标记 `done` 的状态
