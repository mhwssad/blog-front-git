# 阶段五：Mock联调与验收收尾

[返回总栏](./后台管理完善计划.md) | [对应清单](./阶段五-Mock联调与验收收尾-任务清单.md) | [上一阶段](./阶段四-后台首页与总览建设.md)

## 1. 阶段目标

确保后台所有纳入范围的模块，在当前默认 Mock 环境下完成可演示、可联调、可验收的最终收口。

## 2. 当前阶段范围

- Mock 文件覆盖
- 测试数据覆盖
- 菜单与权限演示链路
- README 与任务文档同步
- 工程验证

## 3. 当前基线

- `system-follow.mock.ts`
- `system-file.mock.ts`
- `system-chat.mock.ts`
- `mock/test-data.json`

以上已存在首版，但仍需对菜单、权限、账号体验、文档说明和最终验证做正式收尾。

## 4. 输入条件

- 阶段一至阶段四的收口结果
- 当前菜单权限体系
- 当前环境变量和 Mock 策略

## 5. 输出交付物

- 完整的后台 Mock 演示链路
- 阶段验收记录
- README 与任务文档同步结果
- 工程验证结果

## 6. 实施策略

- 先确认 Mock 数据源是否覆盖模块能力
- 再确认菜单、权限与演示账号体验
- 最后统一做文档同步和工程验证

## 7. 任务域

- Mock 文件与测试数据
- 菜单权限和演示账号
- 文档同步
- 工程验证

## 8. 风险与阻塞

- 如果 Mock 数据与页面链路不同步，会导致阶段二和阶段四验收失真
- 如果菜单权限和演示账号不完整，会影响后台完整演示
- 如果只更新代码不更新文档，后续执行者仍会依赖隐式知识

## 9. 验收标准

- 默认 Mock 环境下可进入所有纳入范围的后台模块
- 管理员账号可完成核心后台操作流
- README、总栏、阶段文档和阶段清单同步完成
- 工程验证通过
