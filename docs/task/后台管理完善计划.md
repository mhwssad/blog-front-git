# 后台管理完善计划

## 1. 文档定位

本文档作为后台管理建设的总栏文档使用，负责维护以下内容：

- 后台建设总目标
- 当前仓库基线状态
- 阶段划分与优先级
- 阶段文档与阶段任务清单入口
- 统一状态约定
- 统一执行约束
- 总体验收标准与完成定义

后续执行顺序统一以本总栏和各阶段清单为准，不再额外创建平铺的临时任务说明。

## 2. 当前目标

当前后台建设目标仍然保持不变：

- 后台可访问
- 后台可查询
- 后台可操作
- 后台可联调
- 后台可扩展

本轮重点不是新增业务边界，而是在现有 API 文档范围内，把后台管理做成一套可持续迭代、可按阶段收口的完整系统。

## 3. 当前仓库基线

### 3.1 已有后台能力

- 后台主入口：`/admin`
- 固定后台首页：`/admin/dashboard`
- 后台布局、菜单、路由守卫、标签页、按钮权限已接入
- 当前默认运行方式：全量 Mock
- 现有后台请求层、Store 分层、菜单映射和日志基础设施已具备

### 3.2 当前已落地的后台页面

#### 系统管理域

- `user`
- `role`
- `menu`
- `config`
- `notice`
- `log`

#### 内容管理域

- `article`
- `category`
- `tag`
- `comment`
- `collection`
- `interaction`
- `follow`
- `file`
- `chat`
- `footprint`

### 3.3 当前需要明确收口的事项

- `follow / file / chat` 已有首版页面、Store 和 Mock，但仍需阶段化验收与收口
- 后台首页已存在总览首版，但仍需按阶段四标准继续验收与优化
- `footprint` 已补齐后台页面、Store、菜单权限和 Mock 删除链路，后续纳入阶段三统一治理
- 已有模块的一致性治理仍未系统推进
- README、阶段文档、最终联调验收尚未形成闭环

## 5. 当前推荐执行顺序

由于仓库里已经存在阶段二和阶段四的首版实现，后续推进顺序按下面执行：

1. 先完成阶段一，输出准确的后台基线结论
2. 再完成阶段二，对 `follow / file / chat` 做正式收口和验收
3. 同步完成阶段四，对首页总览做联动校验
4. 再推进阶段五，完成 Mock、文档、联调与工程验证闭环
5. 最后集中完成阶段三，统一已有后台模块的交互和结构

说明：

- 阶段编号不变
- 当前推荐执行顺序是基于仓库现状做的收口顺序，不改变阶段定义

## 6. 统一状态说明

所有阶段清单和子任务统一使用以下状态：

- `todo`：未开始
- `doing`：进行中
- `blocked`：被阻塞
- `done`：已完成

使用规则：

- 阶段文档记录“阶段目标、边界、依赖、验收”
- 阶段清单记录“当前任务、状态、交付物、验证方式”
- 执行任务时优先更新阶段清单
- 阶段目标变化时，先更新阶段文档，再更新阶段清单

## 7. 统一执行约束

本总栏只保留执行所需的结构约束，不重复已有编码细则。

- 目录结构、模块落点、Mock 组织遵循 `docs/project-structure-convention.md`
- 代码实现细节遵循 `docs/code-writing-convention.md`
- 动态菜单与路由映射遵循 `docs/code-writing-convention.md`（Router 规范章节）
- 基础命令、提交流程和最低验证标准遵循 `AGENTS.md`
- 后台页面必须放在 `src/views/admin/**`
- 后台 API 必须放在 `src/api/sys/**`
- 共享状态统一落在 `src/stores/modules/**`
- 新增或补齐后台模块时必须同步补 Mock，不允许只补页面或只补 API

## 8. 总体验收标准

### 8.1 路由与权限

- 所有纳入后台范围的模块都能通过固定路由或菜单访问
- 页面级访问控制正确
- 按钮级权限显示与禁用逻辑正确

### 8.2 功能闭环

- 每个后台模块至少支持分页查询和基础筛选
- 具备治理动作的模块应提供详情、状态切换、删除或治理能力
- 模块的页面、Store、API、Mock 四层链路完整

### 8.3 Mock 闭环

- 默认 Mock 环境下可进入所有后台模块
- 重点后台域的测试数据完整且可演示
- 菜单、权限、账号体验与 Mock 数据一致

### 8.4 工程验证

至少通过：

```sh
pnpm type-check
pnpm build
```

如涉及范围较大，建议补充：

```sh
pnpm lint
```

## 9. 完成定义

当以下条件同时满足时，视为后台管理任务体系对应的建设任务完成：

- 五个阶段均完成收口
- 阶段清单中无遗留 `doing` 或 `blocked` 项
- `follow / file / chat` 完成正式验收
- 后台首页总览满足阶段四标准
- 已有后台模块完成一致性治理
- Mock、菜单、权限、README、阶段文档同步完成
- 工程验证通过
