# 阶段一：后台基础闭环校准

[返回总栏](./后台管理完善计划.md) | [对应清单](./阶段一-后台基础闭环校准-任务清单.md) | [下一阶段](./阶段二-缺失后台模块补齐.md)

## 1. 阶段目标

输出一份准确、可执行的后台基线结论，明确哪些模块已经闭环、哪些模块只是首版落地、哪些能力仍存在结构缺口。

## 2. 当前阶段范围

本阶段只做校准，不做大规模功能扩写。范围包括：

- 后台现有模块盘点
- 固定首页、动态菜单、路由守卫、标签页、按钮权限链路校验
- 模块边界与落点校验
- 后台现状与计划文档的一致性校验

## 3. 当前已知基线

- `follow / file / chat` 已有页面、Store 和 Mock 首版
- 后台首页已有总览首版
- `footprint` 已确认纳入后台，并补齐页面、Store、菜单权限与 Mock 删除链路
- 固定首页、动态菜单、路由守卫、标签页和按钮权限链路已校验可用
- 现有系统管理域和内容管理域页面已具备基础结构，但尚未统一治理

## 4. 输入条件

- `docs/project-structure-convention.md`
- `docs/code-writing-convention.md`
- `docs/backend-menu-routing-convention.md`
- `docs/api文档/*`
- 当前 `src/views/admin/**`、`src/api/sys/**`、`src/stores/modules/**`、`mock/**`

## 5. 输出交付物

- 后台模块现状清单
- 后台模块状态分类结果
- 计划与仓库现状的差异说明
- 阶段二至阶段五的准确输入基线

## 6. 实施策略

- 先以代码为准，不以历史计划为准
- 先核对页面、Store、API、Mock 的四层链路，再判断模块状态
- 对不一致项形成结论后回写总栏和阶段文档
- 对 `footprint` 这类计划与现状不一致的模块，在本阶段直接定性并补齐单点缺口

## 7. 模块拆解

### 7.1 基础链路

- 固定后台首页 `/admin/dashboard`
- 动态菜单与组件解析
- 后台布局与标签页
- 页面权限与按钮权限

### 7.2 模块状态分类

- 已有并基本闭环模块
- 已有首版但待正式验收模块
- 计划存在但现状缺页或缺链路模块

## 8. 风险与阻塞

- 如果现状判断不准确，后续阶段会在错误边界上继续推进
- 若 `footprint` 结论不及时回写到总栏与阶段清单，阶段三范围仍会继续漂移
- 如果文档不按代码现状回写，后续执行者仍需要重复盘点

## 9. 验收标准

- 能清晰列出后台模块现状
- 能明确区分 `done / doing / todo` 的阶段输入
- 总栏与阶段文档中的现状表述与仓库一致
- 后续阶段执行者不需要再次做同一轮全局盘点
