# 阶段三：已有后台模块一致性治理

[返回总栏](./后台管理完善计划.md) | [对应清单](./阶段三-已有后台模块一致性治理-任务清单.md) | [上一阶段](./阶段二-缺失后台模块补齐.md) | [下一阶段](./阶段四-后台首页与总览建设.md)

## 1. 阶段目标

把已有后台模块从“各自可用”收口到“结构统一、交互统一、反馈统一、职责清晰”的同一套管理台标准。

## 2. 当前阶段范围

### 系统管理域

- `user`
- `role`
- `menu`
- `config`
- `notice`
- `log`

### 内容管理域

- `article`
- `category`
- `tag`
- `comment`
- `collection`
- `interaction`
- `footprint`

## 3. 输入条件

- 阶段一基线结论
- 阶段二缺失模块正式验收结果
- 现有模块对应 API 文档

## 4. 输出交付物

- 后台模块统一交互标准落地结果
- 模块间一致性治理记录
- 统一后的搜索、表格、详情、状态和提示语行为

## 5. 实施策略

- 按域推进，不交叉混做
- 先系统管理域，再内容管理域
- 每个模块只围绕一致性治理，不做范围外重构
- `footprint` 已纳入后台范围，按内容域统一治理标准推进

## 6. 治理项

- 搜索字段与 API 文档对齐
- 列表页结构统一
- 详情与表单交互统一
- 状态切换、删除、治理动作的提示语统一
- 空状态、加载状态、按钮禁用逻辑统一
- 页面、Store、API 的职责边界清晰化

## 7. 风险与阻塞

- 范围容易失控成“大面积重写”，必须坚持一致性治理而非翻新
- 若前置阶段未完成正式验收，本阶段容易反复返工
- 若模块结构差异过大，需优先统一交互形态而非追求完全同构

## 8. 验收标准

- 系统管理域与内容管理域的列表页体验可被统一描述
- 同类操作的反馈方式一致
- 新开发者进入任意后台模块都能快速理解结构与交互模式
